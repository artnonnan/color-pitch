# 09 · เลือกผู้ใช้ (อาท / Guest) และซิงก์ด้วย Supabase

## สิ่งที่ผู้ใช้เห็น
- **หน้าเลือกผู้ใช้:** เปิดเว็บทุกครั้งจะเจอหน้า "ใครกำลังฝึก?" มีให้เลือก **1. อาท** กับ **2. Guest** คนที่เลือกล่าสุดมีป้าย "ใช้ล่าสุด"
- **แยกข้อมูลกัน:** แต่ละคนมีความคืบหน้าและการตั้งค่าของตัวเอง
- **ชิปในหน้าแรก:** บอกชื่อผู้ใช้และสถานะซิงก์ ("ซิงก์แล้ว", "กำลังซิงก์…", "ออฟไลน์…") แตะเพื่อสลับผู้ใช้ได้ และในหน้าตั้งค่ามีปุ่ม "สลับผู้ใช้"
- **ข้อมูลเดิมไม่หาย:** ความคืบหน้าที่เล่นก่อนมีระบบผู้ใช้ย้ายเข้าโปรไฟล์อาทอัตโนมัติ

## ตามที่เจ้าของเลือก
- **ฐานข้อมูล:** Supabase project ใหม่ แยกจากแอปจัดโต๊ะ
- **อาท:** ไม่มี PIN ใครเปิดเว็บก็เล่นในชื่ออาทได้
- **Guest:** เก็บใน cloud และทุกคนใช้โปรไฟล์ guest ร่วมกัน

## ทำงานยังไง
**ฐานข้อมูล** (`supabase/migrations/001_profiles.sql`)
- ตาราง `cp_profiles` มี 2 แถวคือ `art` และ `guest` เก็บ state ทั้งหมดเป็น jsonb
- อ่านได้ทุกคน แต่เขียนตรงๆ ไม่ได้ ต้องเขียนผ่านฟังก์ชัน `cp_save` เท่านั้น
- `cp_save` รับแค่ 2 ชื่อนี้ และไม่ยอมเอาข้อมูลที่เก่ากว่ามาทับข้อมูลที่ใหม่กว่า (เทียบเวลาที่บันทึก)

**ฝั่งแอป** (`lib/cloud.ts`, `lib/store.tsx`)
- ใช้ fetch เรียก REST API ของ Supabase ตรงๆ ไม่ได้ติดตั้ง SDK เพื่อให้แอปยังเบา
- **ตอนเลือกผู้ใช้:** แสดงข้อมูลในเครื่องทันที แล้วค่อยดึงจาก cloud ฝั่งไหนใหม่กว่าใช้ฝั่งนั้น
- **ตอนบันทึก:** บันทึกในเครื่องทันที แล้วส่งขึ้น cloud หลังเลิกกดประมาณ 2.5 วินาที และตอนปิดหรือสลับแอป
- **ถ้าไม่ได้ตั้งค่า Supabase:** แอปเก็บในเครื่องอย่างเดียวเหมือนเดิม

## ความปลอดภัย
- `config.txt` มีรหัสผ่าน DB และ secret key จึงเพิ่มเข้า `.gitignore` แล้ว
- แอปใช้แค่ URL กับ publishable key ใน `.env.local` ตรวจแล้วว่าไม่มี secret key อยู่ในไฟล์ที่ส่งไปเบราว์เซอร์
- ทดสอบกับ publishable key แล้ว:
  - อ่านข้อมูลได้
  - เขียนลงตารางตรงๆ ไม่ได้ (RLS กันไว้)
  - บันทึกด้วยชื่อโปรไฟล์อื่นนอกจาก art กับ guest ไม่ได้

## การตรวจ
- **`profiles.js` (โหมดในเครื่อง):**
  - หน้าเลือกผู้ใช้ขึ้นทุกครั้งที่เปิด
  - ข้อมูลเก่าย้ายเข้าอาท
  - อาทกับ Guest แยกกันจริง
  - สลับผู้ใช้แล้วกลับมาหน้าเลือก
  - เปิดใหม่แล้วจำคนที่เลือกล่าสุดได้
- **`sync-write.js` แล้วตามด้วย `sync-read.js`:** จำลองเป็น 2 เครื่อง เครื่องแรกเล่นในชื่อ Guest แล้วเครื่องใหม่ได้ข้อมูลเดียวกันจาก cloud
- **บั๊กที่เจอจากการทดสอบรอบแรก:** เครื่องใหม่ที่ยังไม่มีข้อมูลประทับเวลาเป็น "ตอนนี้" เลยดูใหม่กว่าและเขียนข้อมูลว่างทับ cloud แก้แล้ว โดยให้เวลาเริ่มต้นเป็น 0 เพื่อให้ cloud ชนะเสมอ
- ลบแถวทดสอบใน DB ออกแล้ว
- ระหว่างทดสอบอัตโนมัติ cloud ปิดอยู่ (`color-pitch:nocloud`) เพื่อไม่ให้ไปทับข้อมูลจริง

## ข้อจำกัด
- ถ้าสองเครื่องแก้โปรไฟล์เดียวกันตอนออฟไลน์ทั้งคู่ เครื่องที่บันทึกทีหลังจะทับทั้งก้อน
- เว็บจริงบน Vercel จะซิงก์ได้ก็ต่อเมื่อใส่ env 2 ตัว (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`) แล้ว deploy ใหม่
